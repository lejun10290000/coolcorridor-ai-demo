# Top-ten DEMO footfall planning contract

The current map's DEMO-REF links receive deterministic fictional FootfallObservation sidecar records: 15-minute passage-event counts, hourly equivalents, a fictional Malaysia +08:00 window and demo_fixture status/source. They are UI planning fixtures, not surveyed counts or new baseline observations. Existing evidence, snapshots and legacy counts remain unchanged. Rank the ten highest hourly equivalents descending, with stable link-ID tie-breaking; only these links are offered by this planner.

Optional WorkflowState additions: planning_mode (footfall/manual; default footfall) and footfall_planning_workspace schema1 with raw budget text, raw tree_unit_cost_rm and roof_unit_cost_rm text, has_calculated, assume_unknown_exposed boolean and choices keyed by known top-ten link ID (trees/roof/none). Existing manual planning_workspace and historical items remain intact. Defaults: RM20,000 budget, RM500/tree, one assumed tree per8m rounded up, RM200/m of roof rounded up to whole metres, and trees eligible on all ten paths. Costs are fictional editable allowances, not market quotations. Invalid numeric drafts remain correctable; bad optional workspace storage is reset with a warning without discarding published history.

Each top-ten link is a point-to-point existing map path. The Developer chooses one treatment per link (or none), so there is at most one proposal per link. Trees project mixed shade; roof/canopy projects mostly shaded. These are explicit simulated category assumptions, not measured percentages or guaranteed mature-tree performance. Tree/roof quantities use the current illustrative metre length, not surveyed construction dimensions; estimates exclude maintenance and real engineering/site constraints.

Benefit = fictional passage events/hour equivalent × illustrative link length_m × max(0, baseline exposure weight − projected exposure weight). Exposed/mixed/shaded weights are1/0.5/0. Unknown shade remains unknown in published evidence; an explicit planning-only switch assumes weight1 for unknown links (default on for this fictional demo), with a warning. When off, unknown links have unknown benefit and are excluded rather than treated as zero evidence. Already shaded links gain zero and are not funded. Counts across links are not unique pedestrians and total benefit is a relative demand/exposure proxy, not people benefited or measured cooling.

Exhaustive subset search over at most10 chosen proposals maximises this benefit under the budget. No overlapping link benefit is counted twice. Choosing a treatment makes it eligible; budget optimisation decides whether it is funded. Changes to budget, unit costs, treatment or published shade automatically recalculate after the first calculation. Plan output includes selected proposals, costs, remaining budget, benefit and reasons. Scenario output retains status simulated, the latest published baseline version and warnings. A baseline publication (including another same-origin tab) rebuilds benefit/portfolio/scenario; unpublished drafts are excluded, and Residents continue using only published shade. Simulation cannot publish or silently change baseline shade.

The normal Developer entry defaults to this footfall planner. A Planning method selector retains the prior manual-candidate planner and its saved inputs as a separate mode. The selected method is remembered locally. No backend, account or cross-device sync is added.

## Using the demo

1. Open the normal app and enter Developer Mode. Choose **Top 10 demo footfall paths — trees or roof** under Planning method if another method was saved.
2. Inspect ranks1–10 and use **Show path on map** to locate each point-to-point link. The inspector shows the same fictional count, units/window and source.
3. Keep or edit the assumed unit prices. Every card shows both quantities/prices: trees and roof/canopy. Select either treatment, or **No proposal / exclude this path**.
4. Enter the budget and choose **Optimise plan**. Funding is a portfolio decision; an individually affordable option may remain unfunded. After the first calculation, changes recompute automatically. There is no editable arbitrary benefit score in this mode.
5. **View simulated map** shows funded trees as mixed shade and funded roofs as mostly shaded. The comparison includes current baseline, treatment price and assumed benefit. Neither choice changes Residents' map.
6. A separate reviewed manual Developer publication refreshes all planning results automatically. A link already shaded to the proposed category no longer needs that funding. No fictional installation or repair record is created automatically.
